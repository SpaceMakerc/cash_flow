# Веб-сервис для управления движением денежных средств (ДДС)
### Стэк приложения:
### - DRF
### - PostgreSQL

## Описание:

ДДС (движение денежных средств) — это процесс учета, управления и анализа
поступлений и списаний денежных средств компании или частного лица.

Данный сервис позволяет пользователям создавать, редактировать, удалять и просматривать записи о движении денежных средств.

## В базе данных сформировано 6 сущностей, из которых одна модель пользователя, 5 оставшихся для формирования записей о ДДС:

**CustomUsers** - модель пользователя (базовая модель User в Django)

|id|username|email|password|is_admin|is_active|
|-|-|-|-|-|-|
|Уникальный идентификатор|Логин|Почта|Пароль|Статус admin|Статус активный|

**Statuses** - Таблица статусов двежения денежных средств. В таблице есть ссылка на пользователей, чтобы каждый пользователь мог добавлять свои статусы и только он мог их видеть (включая статусы базового 
пользователя)

|id|user|is_common|name|
|-|-|-|-|
|Уникальный идентификатор|ID пользователя|Флаг общего статуса|Наименование|

**Types** - Таблица типов движения денежных средств. В таблице есть ссылка на пользователей, чтобы каждый пользователь мог добавлять свои типы и только он мог их видеть (включая статусы базового пользователя)

|id|user|is_common|name|
|-|-|-|-|
|Уникальный идентификатор|ID пользователя|Флаг общего статуса|Наименование|

**Categories** - Таблица категорий движения денежных средств. В таблице есть ссылка на пользователей, чтобы каждый пользователь мог добавлять свои категории и только он мог их видеть 
(включая статусы базового пользователя)

|id|name|type|user|
|-|-|-|-|
|Уникальный идентификатор|Наименование|ID типа ДДС|ID пользователя|

**SubCategories** - Таблица подкатегорий движения денежных средств.

|id|category|name|
|-|-|-|
|Уникальный идентификатор|ID категории ДДС|Наименование подкатегории|

**CashData** - Таблица с общей информацией о движении денежных средств.

|id|created_at|status|type|category|subcategory|sum|comment|user|
|-|-|-|-|-|-|-|-|-|
|Уникальный идентификатор|Дата создания записи|ID статуса ДДС|ID типа ДДС|ID категории ДДС|ID подкатегории ДДС|Сумма|комментарий|ID пользователя|

В отношения присутствуют следующие зависимости:

Types -> Categories, Categories -> SubCategories

У каждой категории есть свой тип, к которому она привязана. У каждой подкатегории есть своя категория, к которому она привязана.

### Аутентификация/авторизация

Сервис поддерживает регистрацию посредством введения логина и пароля с почтой. Для аутентификации в сервисе используется базовая схема с введением username/password и последующим определением пользователя по 
session_id, который хранится на строне клиента к cookies и в бд. Доступ к информации есть у всех авторизированных пользователей.

### Инструкция по запуску:

![project_tree](https://github.com/user-attachments/assets/a02a23a7-3e4c-4e32-bbfd-793b5f1fdca1)


1 - Склонировать проект
https://github.com/SpaceMakerc/cash_flow.git

2 - Для запуска приложения первоначально нужно создать файл .env в корне проекта, в нём указать следующие данные:

SECRET_KEY=ключ к приложению в Django

DATABASE_NAME=наименование базы

DATABASE_USER=имя пользователя

DATABASE_PASSWORD=пароль

DATABASE_HOST=хост

DATABASE_PORT=порт

Если используется контейнер с БД, то в модуле проекта settings необходимо указать название контейнера в переменную DATABASE -> host

Пример:
DATABASES = {
    'default': {
        'ENGINE': 'django.db.backends.postgresql',
        'NAME': os.getenv('DATABASE_TEST_NAME'),
        'USER': os.getenv('DATABASE_TEST_USER'),
        'PASSWORD': os.getenv('DATABASE_TEST_PASSWORD'),
        'HOST': "pgdb",  #  Наименование контейнера для базы данных в Docker Compose
        # ИЛИ os.getenv('DATABASE_HOST') для локальной бд с добавление модуля --network host в docker-compose.yml (чтобы контейнер увидел локальную дб)
        'PORT': os.getenv('DATABASE_TEST_PORT'),
    }
}

3 - Подготовка приложения. Установка зависимостей прописана в файле Dockerfile, который также содержит подготовительные команды для приложения Django и запуск файла docker-entrypoint.sh (указан ниже)

4 - запустить docker командой docker-compose up -d

Для выполнения миграций и наполнения бд базовыми данными в проекте указан файл docker-entrypoint.sh. Он содердит три команды:
echo "Apply database migrations"
python manage.py migrate

echo "Apply adding base data"
python manage.py migrate_data

echo "Running server"
gunicorn api_service.wsgi:application --bind 0.0.0.0:8000 --workers 1

Первая выполняет миграции, вторая заполняет бд базовыми данными, третья запускает gunicorn.
